# Zirva — сайт и админка

React + Vite для сайта, Go для API и админки. Админка позволяет менять тексты всех разделов, заголовки, подписи, реквизиты, фотографии и логотип. Заявки из формы сохраняются на сервере; доступны поиск, фильтрация и статусы «Новая», «В работе», «Завершена».

## Локальный запуск (Windows / PowerShell)

Нужны Node.js 22+ и Go 1.26.4+. Команды выполняются в папке проекта.

1. Установите зависимости:

   ```powershell
   npm install
   ```

2. Если файла `.env` ещё нет, скопируйте `.env.example` в `.env` и заполните `ADMIN_PASSWORD` своим паролем длиной 12–72 байта. Логин задаётся через `ADMIN_USERNAME`, по умолчанию `admin`.

   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```

   `.env` исключён из Git. Не добавляйте пароль в переменные с префиксом `VITE_`: они публичны.

3. Соберите сайт и запустите Go:

   ```powershell
   npm run build
   npm run dev:backend
   ```

   Сайт: **http://localhost:8080**. Админка: **http://localhost:8080/admin/**.

4. Для разработки React откройте второй терминал:

   ```powershell
   npm run dev
   ```

   Сайт будет доступен на **http://localhost:5173**. Vite проксирует `/api` и `/media` на Go-сервер. Админку открывайте напрямую на порту 8080. Оба процесса должны работать одновременно.

При изменении Go или файлов админки перезапустите `npm run dev:backend`. После редактирования через админку достаточно сохранить изменения и обновить сайт; пересборка не нужна.

## Docker

Запустите Docker Desktop. В `.env` задайте пароль, затем:

```bash
docker compose up --build -d
```

Сайт и админка доступны по тем же адресам на порту 8080. Один контейнер собирает React и запускает Go. Данные находятся в постоянном volume `zirva-data`.

```bash
docker compose logs -f
docker compose down
```

Обычный `down` сохраняет данные; `down -v` удаляет volume вместе с заявками и фотографиями. Для публикации в интернете нужен сервер с HTTPS-прокси, который сохраняет заголовок `Host`; задайте `COOKIE_SECURE=true`. Порт Docker привязан к localhost для работы через такой прокси.

Переменные `.env` передаются контейнеру через [Docker Compose](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/).

## GitHub Pages + отдельный Go-сервер

[GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) размещает статический сайт. Go-сервер, админка, заявки и загрузки требуют отдельного хостинга.

Когда будет хостинг:

1. Разверните Docker-контейнер на сервере с постоянным диском и HTTPS.
2. На сервере установите `PUBLIC_ORIGINS=https://xuwdil007.github.io` и `COOKIE_SECURE=true`. Origin указывается **без** `/zirva/`.
3. В репозитории откройте **Settings → Secrets and variables → Actions → Variables** и создайте `VITE_API_URL` со значением HTTPS-адреса Go-сервера, например `https://api.example.com` (без `/api` и без завершающего `/`). Это публичный адрес, не пароль.
4. Отправьте изменения в `main`/`master` или запустите workflow **Deploy Zirva to GitHub Pages**. Он уже читает эту переменную.
5. Открывайте админку по адресу `https://api.example.com/admin/`.

До подключения API сайт показывает исходный контент. При недоступном API форма сообщает об ошибке и сохраняет введённые данные, а не показывает ложное подтверждение. Отправка через почтовое приложение больше не используется. Телефон и email остаются обычными рабочими ссылками.

## Хранение и ограничения

- `backend/content/default.json` — исходный каталог контента, сгруппированный по разделам; используется React и Go.
- `backend/data/state.json` — сохранённые тексты и заявки при локальном запуске.
- `backend/data/uploads/` — загруженные JPEG/PNG (до 8 МБ, до 40 Мп). SVG-загрузки отключены; исходный SVG-логотип работает, заменить его можно прозрачным PNG.
- В Docker те же файлы находятся в `/data`.
- Хранилище рассчитано на **один процесс Go** и небольшой корпоративный сайт. Записи защищены mutex и сохраняются через временный файл с последующей заменой. Для нескольких экземпляров сервера или большого объёма заявок потребуется общая БД.
- Для резервной копии остановите сервер и скопируйте **весь** каталог данных / volume, затем запустите снова. Восстановление — вернуть копию при остановленном сервере. Не публикуйте эти файлы: они содержат контакты клиентов.
- Один администратор задаётся переменными окружения. Для смены пароля измените `.env` и перезапустите сервер (Docker: `docker compose up -d`). Сессии истекают через 12 часов и сбрасываются при перезапуске.
- Пароль проверяется через bcrypt. Сессия — HttpOnly/SameSite cookie, изменения требуют CSRF-токен. Есть проверка Origin, ограничение размеров запросов и частоты входа/заявок (10 попыток за 10 минут на IP).
- Сервер намеренно не доверяет `X-Forwarded-For`. За reverse proxy ограничение частоты применяется к адресу прокси, то есть совместно для посетителей; для большого трафика перенесите лимиты на доверенный прокси и настройте идентификацию IP.
- Конфликт параллельного редактирования контента возвращает ошибку вместо перезаписи чужих изменений.
- Неиспользованные загруженные фотографии автоматически не удаляются. Заявки сохраняются до ручного обслуживания хранилища; интерфейс не отправляет их в email или мессенджеры.
- Title и description обновляются в браузере; серверного рендеринга динамических SEO-метаданных нет.

## Проверка

```bash
npm run build
npm run test:backend
npx playwright install chromium
npm run test:admin
```

`test:admin` запускает отдельный Go-сервер на 8123 с временным хранилищем и случайным тестовым паролем. Проверяет настоящую отправку формы, вход, статусы заявок, редактирование текста и фото, ошибки сети, мобильную вёрстку и сохранность данных после перезапуска. Основные данные сайта тест не изменяет.

Дополнительная UI-проверка при запущенном Vite: `node scripts/check-site.mjs`. Скриншоты — в `artifacts/`.

## Источники и оформление

Контент и оформление основаны на «ББ Зирва (2).pdf», июнь 2026: страницы 3–5 — история, позиционирование, миссия, видение и ценности; 7, 11–13 — логотип и цвета; 17 — реквизиты; 19 и 31 — иллюстрации. Направления и этапы дополнены редакционными формулировками. Изображения служат иллюстрациями, не портфолио реализованных объектов.

Шрифт — Inter 400/500 из `@fontsource/inter`, поставляется локально. Палитра и адаптивные стили сайта — `src/styles.css`. Компоненты разделены по разделам. Анимации и прежнее поведение курсора сохранены.

## Возврат прежнего текста

Под каждым текстовым полем есть «Отменить правку поля» (отмена несохранённого ввода) и «Прежние варианты текста». Выберите вариант, просмотрите его и нажмите «Вернуть этот текст», затем «Сохранить изменения». Остальные поля остаются без изменений. Само восстановление тоже можно отменить через историю.

Хранятся последние 30 предыдущих вариантов каждого изменённого текстового поля, включая даты изменения, плюс исходный текст сайта. История записывается вместе с контентом и сохраняется после перезапуска. История начинает накапливаться с установки этой функции: промежуточные варианты старых правок до обновления недоступны. Фотографии эта функция не восстанавливает.
